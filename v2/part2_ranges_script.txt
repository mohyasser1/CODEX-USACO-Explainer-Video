PART 2 INTRODUCTIONS — RANGE UPDATES AND TWO-DIMENSIONAL PREFIXES
Status: numerical derivations and complete companions, not exhaustive range-query
coverage. Programs difference_updates.cpp and prefix_rectangles.cpp.

[Five time slots initially0. Add3 on[1,4), then2 on[2,5).]
Rohail now needs to add staff to ranges of time
slots. Start with five zero counts, indexed zero
through four. One operation adds three to slots one,
two and three, written as the half-open interval
one through four. Another adds two on the interval
two through five. If we apply every update to
every covered slot immediately, many long updates can require
quadratic work. When all updates happen before the final
values are needed, a difference array offers a simpler
way to record their boundaries.

[Difference array length6. At1 add3; at4 subtract3.]
Record a positive event where an addition starts and an
equal negative event where it stops. Adding three on
one through four means difference one increases by three,
and difference four decreases by three. The right endpoint
is excluded, so that is exactly where the effect
must stop. Allocate n plus one difference slots, because
a stop at boundary n is valid even though there
is no input element at index n. Boundary storage
and element storage have related but different sizes.

[Second update:diff2+=2,diff5-=2. Final difference0,3,2,0,-3,-2.]
For the second update, add two at boundary two
and subtract two at boundary five. The difference array
is now zero, three, two, zero, negative
three, negative two. Those are events, not the
final staff counts. Take a running sum across the
first five positions. The active addition becomes zero,
three, five, five and two. The stop
event at five ensures the second addition ends there,
but it is not printed as a sixth time slot.

[Proof: each update contributesx afterl and cancels at r. Overlapping contributions
add; empty interval updates cancel at the same boundary.]
For one update, its start event contributes x to
every later prefix sum, while its stop event cancels
that contribution from r onward. The net effect is
exactly x inside the requested half-open interval and zero
outside it. Multiple updates work because their contributions add.
If l equals r, the two events occur at
the same boundary and cancel, correctly changing nothing.
Negative additions work too. The proof concerns additive updates;
it does not automatically justify replacing a range with a
value or taking a minimum using the same two events.

[Cost n+q, contrasted with interleaved queries requiring another structure.]
Each update changes two entries, so q updates cost
order q time. Reconstruction scans n positions, giving
order n plus q total time and linear storage.
If we need answers between every update, repeatedly reconstructing
the whole array may lose the advantage. Later structures
handle different update/query workloads. The correct question is not
whether difference arrays are fast in general, but whether
the required timing of updates and answers matches their strength.

[New grid1,2,3 /4,5,6 /7,8,9. Prefix boundaries0..3 on both axes.]
Now extend prefix sums to a grid. Imagine a
small attendance table with rows and columns. Our example
is the three-by-three grid containing one through nine in
row-major order. Define P of r,c as the
sum of rows before r and columns before c.
The prefix table has one extra zero row and
one extra zero column. Again, entries represent boundaries.
A zero boundary means an empty region, which lets
edge-touching queries use the same formula as interior queries.

[Construction at bottom-right:9+P[2][3]21+P[3][2]27-P[2][2]12=45.]
To build the entry just beyond one cell, take
the prefix above, add the prefix to the left,
subtract their overlap and include the new cell. At
the bottom-right, that is nine plus twenty-one plus
twenty-seven minus twelve, giving forty-five. We subtract the
overlap because it was included in both larger prefixes.
The same inclusion-exclusion idea will answer queries. Trace one
entry numerically before treating the formula as a symbol
pattern to memorize.

[Query rows[1,3),cols[1,3): cells5,6,8,9. Four shaded regions animate.
45 minus top strip6 minus left strip12 plus overlap1 =28.]
Ask for rows one through three and columns one
through three, both half-open. The desired cells are
five, six, eight and nine, totaling twenty-eight.
Start with the large prefix forty-five. Subtract the top
strip, whose sum is six. Subtract the left
strip, whose sum is twelve. The top-left cell
one belonged to both unwanted strips, so it has
now been subtracted twice. Add it back once. Forty-five
minus six minus twelve plus one gives twenty-eight.

[General rectangle formula with each boundary tied to a shaded region.]
For boundaries r one, c one, r two,
c two, the formula is P at r two,
c two, minus P at r one,c two,
minus P at r two,c one, plus P
at r one,c one. The picture explains every
term. If a rectangle has zero height or width,
the terms cancel and the answer is zero. If
it begins at row zero or column zero, the
corresponding prefix strip is zero. Do not insert extra
minus ones unless converting from a different inclusive coordinate
convention at the input boundary.

[Cost rows*cols preprocessing, constant query; wide type and dense-memory warning.]
A dense prefix table takes order rows times columns
time and storage to build, then constant work per
rectangle query. Use a wide enough integer for region
sums, not merely for individual cells. With a
million cells each of magnitude at most a billion,
long long handles sums of up to one quadrillion in magnitude. A
huge sparse coordinate range may make a dense table
impossible, even if few cells contain data. Compression
preserves ordering but does not automatically preserve area or
distance, so it is not a universal replacement.

[Transfer cards: earlier range-update result; grid query[0,2)x[1,3).]
Pause and reconstruct the two one-dimensional updates without looking
at the finished array. Then query the first two
rows and last two columns of the grid. The
range-update result is zero, three, five, five,
two. The rectangle contains two, three, five,
six, totaling sixteen. Our tests compare difference updates
with direct element-by-element additions, and grid queries with
direct rectangle scans. They include empty intervals and rectangles,
negative values and boundaries at the final row or
column, where off-by-one errors often reveal themselves.
