[Quadratic state dp[i]=length of longest increasing subsequence ending exactly at i.]
Define dp at i as the length of the longest strictly increasing subsequence that ends exactly at position i. The word exactly matters. Every position can form a one-element subsequence by itself, so initialize its value to one. To extend a subsequence ending at an earlier position j, require both that j is before i and that its value is smaller than the value at i. Then dp at j plus one is a candidate for dp at i. Take the largest candidate, or keep one if no extension exists. The overall answer is the largest dp value, not necessarily the value at the last position.

[DP trace values3,1,2,5,4,6 ->lengths1,1,2,3,3,4.]
At the first score, three, the ending length is one. At the next score, one, no earlier smaller value exists, so its length is also one. Score two can extend the earlier one, giving length two. Score five can extend the chain one, two, giving length three. Score four can also extend one, two, so its ending length is three even though it is smaller than the previous score. Finally six can extend either length-three chain, giving four. The DP row is one, one, two, three, three, four. Each cell has a witness ending at its own position; the row itself is not a sequence of chosen scores.

[Proof:last predecessor j; valid extension; all possible predecessors considered.]
Why does this recurrence work? Any increasing subsequence ending at i either consists only of that position or has a previous selected position j. That j must be earlier and have a smaller value. Removing the final element leaves a valid subsequence ending at j, whose best possible length is represented by dp at j. Conversely, extending any such valid earlier subsequence with the current value produces a valid candidate. Considering every eligible predecessor therefore captures the optimum. This is the same discipline as the coin recurrence: define the state, describe the final choice, and prove that the candidates are both valid and complete.

[Cost n^2 predecessor comparisons;n200000 too large. Need a different summary.]
The simple DP checks up to n earlier positions for each of n positions, so it takes quadratic time and linear storage. It is excellent for learning and for checking small cases, but two hundred thousand scores would imply far too many predecessor comparisons. Maya asks what information about an earlier chain actually matters when trying to extend it. Its full history is not needed for a length-only answer. Among chains of the same length, the one ending at a smaller value is at least as easy to extend with a future score. That comparison suggests a more compact summary.

[Define tails[length-1]=smallest possible ending value for an increasing subsequence of that length in processed prefix.]
Let tails at index length minus one store the smallest possible ending value of any strictly increasing subsequence of that length among the scores already processed. This is a statement about possibilities, not one shared sequence. A smaller ending is better for future extension because every future value that can extend a larger ending can also extend the smaller one. Rohail compares two length-three chains ending at five and four. Keeping four as the best ending does not claim that the earlier five never existed; it says four is the stronger summary for answering future length questions.

[Trace tails:3 ->1 ->1,2 ->1,2,5 ->1,2,4 ->1,2,4,6.]
Process three: there is a length-one chain ending at three, so tails contains three. Process one: it improves the best ending for length one, replacing three. Process two: it is larger than the current final tail, so it extends to a new length and tails becomes one, two. Process five: append it, giving one, two, five. Process four: replace five with four, because the smaller ending is better for length three. Process six: append it, producing one, two, four, six. The number of entries is four, the same answer as the quadratic DP. This example shows replacement improving an existing length rather than always increasing the answer.

[Use lower_bound: first tail>=x. Replace there; append if no such tail.]
For each new value x, find the first tail that is greater than or equal to x. That is lower bound. If no such entry exists, x is larger than every current best ending and extends the longest length, so append it. Otherwise replace that entry with x. The tail values remain strictly increasing, which permits binary search. The entry just before the replacement, if one exists, is strictly smaller than x, so a chain of that shorter length can be extended. We are searching over the current tails array, not sorting the input or moving the current score to a new time in the original history.

[Strict duplicate test2,2,2:tails stays[2],length1. upper_bound would append and give3.]
Maya tests the word strictly with three copies of two. The first creates one tail. Each later two finds that same first entry because it is greater than or equal to two, so the array stays length one. If Rohail used upper bound, which finds the first strictly greater entry, equal twos would be appended and the answer would become three. That would solve the nondecreasing variant, where equality is allowed, rather than strict increasing order. The difference between the two binary-search functions is therefore part of the mathematical contract, not a stylistic preference about standard-library names.

[Why earliest replace index p gives best length p+1; cannot extend longer than p+1.]
Suppose lower bound returns position p. All preceding tails are smaller than x, so if p is positive, a subsequence of length p ending at the previous tail can be extended to length p plus one. If p is zero, x alone provides length one. No longer subsequence ending at x can be formed from the processed prefix: that would require an earlier subsequence of length at least p plus one with ending value smaller than x, contradicting the minimal-tail definition and the choice of p. Replacing the old tail preserves the best ending for this length, while other lengths keep their existing witnesses. This explains both the binary-search position and why one replacement suffices.

[Tails are not necessarily one subsequence: input2,3,1 ->tails1,3;1 occurs after3.]
Rohail is about to print tails as the actual answer sequence. Maya gives him two, three, one. After the first two values, tails is two, three. The final one improves the length-one tail, leaving one, three. But one appears after three in the input, so one, three is not an actual subsequence of this input. The length two remains correct because two, three was a valid earlier witness. This example exposes exactly what the summary forgets. If the problem asks for a witness, store additional predecessor and index information during processing. Our companion returns only the length and does not pretend the tails values are a reconstructed path.

[Implementation vector<long long>tails;lower_bound;replace or push_back. No iterator reuse after growth.]
The complete implementation maintains a vector of tail values. Lower bound returns an iterator. If it equals end, append x; otherwise assign x through the iterator. We do not use that old iterator after appending, because vector growth may reallocate its storage. The count of tails never exceeds the input length. Each search takes logarithmic time in the current tail count, giving order n log n total time and linear storage in the worst case. An empty sequence returns zero. Negative values are allowed because the method uses comparisons rather than assuming every score is positive; the story's invented scores do not restrict the mathematical input contract.
