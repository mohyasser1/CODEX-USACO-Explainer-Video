PART 3 GUIDED LAB — FIND A ROUTE THROUGH THE SEATING PLAN
Status: grid BFS worked implementation. Program grid_routes.cpp.

[Grid3x4: S..# / .#.. / ...T. Four-direction moves, no diagonals, each move costs1.]
Maya gives Rohail a seating-plan grid rather than a list of hallway edges. The first row is start, open, open, wall. The second is open, wall, open, open. The third is open, open, open, target. A volunteer can move one square up, right, down or left, provided the destination is inside the grid and not a wall. Every move costs one step. Find a shortest route from S to T, or report that none exists. This is a new map with its own input, not a secret extra hallway in the earlier room graph.

[Coordinates(row,column),both zero-based. Start(0,0),target(2,3).]
Rohail wants to number every square by hand and write an adjacency list. Maya asks whether the neighbors can be generated directly from a coordinate. At row r and column c, the four candidates are r minus one with c, r with c plus one, r plus one with c, and r with c minus one. The movement rules generate an implicit graph. Open cells are vertices, and allowed single moves are edges. We can run the same BFS reasoning without storing all those edges. The grid is a compact description of the graph, not a completely unrelated algorithm family.

[Flat ID=r*width+c;inverse row=id/width,column=id%width. Width4.]
For the queue and parent array, our program uses a flat integer ID. Multiply the row by the width and add the column. With width four, row one column two has ID six. Dividing six by four gives row one, and six modulo four gives column two. This is integer division doing exactly the job we want. The mapping preserves a unique label for every cell, but neighboring IDs are not automatically neighboring cells. IDs three and four lie on opposite ends of different rows. That is why neighbor generation still uses coordinates and explicit bounds, rather than blindly adding one to an ID.

[Wrong candidate from(0,0):up(-1,0),left(0,-1). Bounds before indexing.]
At the start, moving up would produce row negative one, and moving left would produce column negative one. Rohail almost reads those cells before checking whether they exist. Maya stops him at the boundary test. First reject coordinates outside the grid. Only then inspect the destination character to see whether it is a wall. The order matters: a check performed after an invalid access does not undo the access. This is the same short-circuit habit from our first C plus plus lesson, now attached to a visible top edge and left edge. A safe candidate is one whose coordinates have already passed both bounds.

[Queue order up,right,down,left. Startdist0;discover(0,1),(1,0),bothdist1.]
Initialize every distance to negative one and every parent to negative one. Put the start in the queue with distance zero. Processing the start rejects up and left, but discovers the open cells to the right and below. They both receive distance one and parent equal to the start. Because our neighbor order is up, right, down, left, the right cell enters first. Another consistent neighbor order could produce a different shortest route in a tie. It would not change the shortest distance. The output contract asks for one valid shortest route, so our tests must allow that freedom.

[Pop(0,1):discover(0,2)dist2. Pop(1,0):discover(2,0)dist2.]
Process row zero column one. Its right neighbor is open and new, so row zero column two receives distance two. Its downward neighbor is the wall at row one column one, so it is not enqueued. Then process row one column zero. It discovers row two column zero at distance two. The queue now contains those two distance-two cells. Rohail notices that the wall has redirected the possible routes, but it has not changed the queue's layer discipline. Both one-step cells were processed before either two-step cell. The shortest-path proof still depends on equal move cost, not on the map being rectangular.

[Next layers:(1,2),(2,1)dist3;then(1,3),(2,2)dist4;target(2,3)dist5.]
Processing the two distance-two cells discovers row one column two and row two column one, both at distance three. Next, row one column two discovers row one column three and row two column two at distance four. The other distance-three cell sees that row two column two is already discovered and does not add another copy. Finally, row one column three discovers the target below it at distance five. The alternative approach from row two column two also reaches the target, but its distance and parent are already recorded. Keeping the first shortest route is enough for this contract.

[Parent route(0,0)->(0,1)->(0,2)->(1,2)->(1,3)->(2,3). Five moves,six cells.]
Follow parents backward from the target and reverse the collected sequence. Our chosen route goes right, right, down, right, down, for five moves. It contains six cells because a route includes both endpoints. Sam counts six coordinates and announces six steps. Rohail asks him to count the transitions between consecutive coordinates instead. That distinction is small but appears everywhere in graph problems: number of vertices on a nonempty path and number of edges along it differ by one. The printed distance should agree with the number of adjacent moves in the reconstructed route, not simply with the length of the coordinate list.

[Check witness:inside bounds,notwall,Manhattan neighbor distance1;start/end correct.]
Maya checks the route without rerunning the same BFS code. It begins at S, ends at T, and every coordinate is an open cell inside the grid. Each consecutive pair differs by one in exactly one coordinate, so every move is legal. The route uses five moves. To prove it is shortest, we still need the BFS layer argument or an independent distance oracle; merely drawing a legal route does not prove optimality. A witness check and an optimality check answer different questions. Our automated tests do both, which prevents a correct distance paired with an invented route from slipping through unnoticed.

[Code:validate unique S,T;distance flat array;front then pop;bounds;wall;visited;parent.]
Read the complete program from those state meanings. It validates the grid dimensions, every row's length, the allowed characters and the presence of exactly one start and one target. The queue stores flat IDs, while neighbor calculations temporarily use row and column. After a candidate passes bounds and wall checks, its distance marker determines whether it is new. On first discovery, assign distance, record parent and enqueue it. The code does not overwrite parents on later visits. If the target remains undiscovered, print negative one and stop before following parents. A missing route should not become a one-cell list containing only the target.

[Complexity at mostH*Wcells,4candidateedges each. StorageO(HW).]
There are at most height times width cells, and each processed open cell considers four candidates. That gives linear time in the number of grid cells, with linear storage for the grid, distance array, parent array and queue. A recursive flood fill might also find reachability, but a long narrow open region can create deep recursion. Our explicit queue avoids using the language call stack for that traversal. This does not mean every recursive graph program is wrong; it means implementation limits must be considered alongside the mathematical algorithm. The grid bounds in our program keep the flat ID multiplication within int range.

[Changed model:diagonals allowed,or terrain costs,or key-held bit. Each requires explicit change.]
Rohail asks whether the program can now solve every maze. Maya changes one rule at a time. If diagonal movement is allowed, the neighbor set changes. If stepping onto different cells has different nonnegative costs, ordinary equal-step BFS no longer minimizes total cost. If a key changes which doors can be opened, position alone may no longer describe the state. Two visits to the same cell with different key status can have different future options. The reusable lesson is the modeling process, not a promise that one queue routine handles every story containing walls and a destination.

[One-key state example:visited[row][col][key0or1]. Do not implement in current companion.]
For one reusable key, an extended model could store whether the key has been collected as an extra bit. Visiting a cell without the key would not prevent visiting that same cell later with the key. There would be up to twice as many states, and moving through a locked door would depend on the bit. That is a modeling extension, not hidden behavior in our current companion program: the current grid accepts only open cells, walls, S and T. Rohail writes the changed state sentence before adding another dimension. Extra arrays should represent meaningful distinctions, not be decorations added because a previous solution happened to use three indices.

[Transfer question:grid2x3 S#. / ..T. Then block(1,1). No answers visible.]
Try a smaller grid. Its first row is S, wall, open. Its second row is open, open, T. Find the shortest distance and one route. Then change row one column one into a wall and decide whether the target is reachable. Finally, explain why the open cell in the top-right corner does not rescue a route if it has no connection to the start's component. Pause the video to trace the queue and the parent chain. Use coordinates consistently; switching between one-based row labels and zero-based array positions halfway through a trace creates a new puzzle nobody requested.

[Answer:first distance3 via(0,0),(1,0),(1,1),(1,2);blocked variant unreachable.]
The first grid has a three-move route: down, right, right. Its coordinate list contains four cells. After blocking row one column one, the start can reach only the cell below it; the target's region is separated, so the answer is negative one. The open top-right cell belongs to the target side and cannot create an edge across the wall. Our independent small-grid oracle explicitly constructs the allowed graph and computes distances using a different method, then checks the returned coordinate path. Rohail can now translate between a picture, an implicit graph, array storage and a verified answer without confusing any one of them for the whole problem.
